# as-is プロジェクト規約の草案プロンプト

既存コードから**観測できる**規約を `doc/conventions.md` に書き出してください。「あるべき規約」ではなく「このリポジトリで現に守られているパターン」を書きます。dev-flow の implementer / reviewer はこのファイルを言語標準の規約より優先して使います。

入力:
- 棚卸し: `{INVENTORY_PATH}`
- 言語標準の規約: `{LANGUAGE_CONVENTIONS_PATH}`（`dev-flow-implementation/reference/conventions/<language>.md`。比較対象）
- リンタ・フォーマッタ設定: `.golangci.yml` / `ruff.toml` / `pyproject.toml` / `.eslintrc*` / `phpstan.neon` / `pint.json` 等を探して Read

## 手順

1. 代表的なファイルを各レイヤから 3〜5 個 Read し、命名（ファイル・型・関数・変数）、ディレクトリ構成、import の並び、エラー処理の書き方、ログの出し方、テストの構造（ファイル配置・命名・フィクスチャ）を抽出する
2. リンタ設定から有効・無効になっているルールを読み取る（無効化されたルールは「意図的に外している」可能性が高い）
3. 言語標準の規約と比較し、異なる点を「言語標準と異なる（意図的か要確認）」と印を付けて列挙する
4. 判断できない点は書かない。3 ファイル以上で一貫しているものだけを「規約」とする
