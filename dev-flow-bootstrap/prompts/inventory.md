# コード棚卸し（inventory）プロンプト

対象範囲のコードを読み、`doc/process/inventory.md` に**機械可読な棚卸し表**を書き出してください。以降の as-is ドキュメント生成はすべてこのファイルを入力にするので、推測を混ぜず「ファイルに書いてあること」だけを記録します。

対象範囲: `{SCOPE}`（空なら リポジトリ全体）
技術スタック: `{tech_stack}`

## 手順

1. `git ls-files {SCOPE}` で対象ファイルを列挙し、実装 / テスト / IaC / 設定 / ドキュメントに分類する
2. エントリポイント（main / サーバ起動 / CLI / ジョブ / ハンドラ登録）を Grep で特定する
3. HTTP ルート・gRPC サービス・GraphQL スキーマ・CLI サブコマンド・イベントハンドラを、フレームワークの登録 API（`router.GET` / `@app.route` / `Route::` 等）から**網羅的に**抽出する
4. DB スキーマ（migrations / ORM モデル / schema ファイル）からテーブル・主要カラムを抽出する
5. 既存テストを列挙し、テスト関数ごとに「何を検証しているか」を 1 行で要約する（テスト名とアサーションから読み取る。読み取れなければ `不明`）
6. IaC（Terraform / CloudFormation / Kubernetes / docker-compose）があればリソース種別と名前を列挙する
7. 外部依存（外部 API 呼び出し・キュー・キャッシュ・メール等）を列挙する

## 出力フォーマット（`doc/process/inventory.md`）

```markdown
# コード棚卸し

対象範囲: ...
実装ファイル数: N / テストファイル数: M / IaC ファイル数: K

## モジュール構成
| ディレクトリ | 役割（1 行） | 主要ファイル |
|---|---|---|

## エントリポイント
| 種別 | ファイル:行 | 説明 |
|---|---|---|

## ルート / インターフェース
| INV-R-NNN | メソッド | パス | ハンドラ（ファイル:関数） | 認証 | 備考 |
|---|---|---|---|---|---|

## データモデル
| テーブル / モデル | 定義ファイル | 主要カラム | 関連 |
|---|---|---|---|

## 既存テスト
| INV-T-NNN | ファイル | テスト関数 | 検証内容（1 行） | 対象ルート/モジュール |
|---|---|---|---|---|

## インフラリソース（IaC）
| 種別 | 名前 | 定義ファイル |
|---|---|---|

## 外部依存
| 種別 | 対象 | 呼び出し箇所 |
|---|---|---|

## 読み取れなかったもの
- （動的ルーティング・メタプログラミング等で静的に追えなかった箇所）
```

`INV-R-NNN` / `INV-T-NNN` は棚卸し内の一時 ID。REQ / TC の採番は後段の writer が行うので、ここでは振らないこと。

完了したら SendMessage は使わず、最終回答として「棚卸し完了: doc/process/inventory.md」と各表の件数、読み取れなかったものの要約を返してください。
